# 项目家 Agent：验收与 RFI 接续设计

## 产品选择

选用“可复用 Agent 接续接口 + 网页参考应用”。网页让评委看见完整业务流程；接口和最小链上摘要对应 Metropolis 的 Trust, Identity & AI Infrastructure 赛道。桌面安装包和完整 SaaS 暂不进入第一版范围。

## Torra 架构中采用的边界

- 会话原文单独保存；新会话的恢复依据是项目级任务 checkpoint，而非拼接全部历史消息。
- 证据片段保存来源文档和段落位置；检索结果不自动构成验收结论。
- RFI 有草稿、已在本地确认、已记录回复的状态；任何外部发送必须由人另行完成。
- RFI 草稿会创建持久 Human Input 暂停点，确认或暂缓都有记录；未回答时不能通过重复分析越过暂停点。
- 项目长期约定由用户显式写入，与会话原文及任务状态分层；当前不做自动记忆抽取。
- 模型回答只是说明或建议；验收通过由确定性的人工确认 API 写入。
- 模型工具仅开放读取、检索、分析和 RFI 草稿；四轮内无进展即停止并保留任务状态。当前只有模拟模型测试，没有真实模型线路结论。
- 项目资料以项目 ID 隔离。当前原型是本地单用户，没有 Torra 的账号/工作空间权限体系。

## 数据流

`项目 → 验收条目 → 资料段落 → 候选证据 → 缺口/RFI → 人工回复 → 重新核验 → 人工确认`。每次状态变化写入 SQLite；新会话读取未完成任务。摘要接口只输出随机 ID、状态和 SHA-256 内容哈希。合约设计只锚定摘要根及调用者，不存业务原文。

## 失败与验证

资料相关性较弱时保留“缺少证据”；发现“未记录/待补”等明确缺口时建议 RFI。模型服务失败时保留消息和任务状态，并明确说明模型未返回。重启后不会自动发出 RFI 或确认验收。自动测试覆盖断点恢复、项目隔离、缺口识别、摘要篡改；浏览器人工路径另行检查。
